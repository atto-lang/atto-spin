# Oreslang HTTP/1.1 transport framing tests — draft 2026-10-18

Issue #10: replace Java JDK HttpServer framing with source-owned async Oreslang std/http and std/net admission while preserving safety.

## Framing acceptance vectors
1. Fragment request line and header fields across reads; parser must buffer within explicit caps and not parse a partial request.
2. Two pipelined requests on one connection; response ordering follows request order regardless of handler suspension.
3. Duplicate divergent `Content-Length` headers: reject, never choose an attacker-controlled value.
4. `Transfer-Encoding` plus `Content-Length`: reject ambiguous boundary (no request smuggling).
5. Chunk extension/trailer overflow, invalid hex length or missing CRLF: deterministic 400 and bounded cleanup.
6. Keep-alive idle timeout vs request completion: exactly one connection termination; no orphan FD or handler.
7. Slow client sends one byte at a time: cumulative byte, header count and deadline ceilings apply.
8. Cancellation after body reservation refunds budget and supervises actor without aborting unrelated requests.

## Proof requirements
Real source-compiled transport with sockets and a bounded DATA/CONTROL ingress queue. Conformance tests must run against parser/host bytes directly; mocked JDK responses do not certify migration. Compare latency, allocations and throughput on exact workload/tree hashes only.

**Status:** source-owned parser test plan only; existing JDK transport remains unchanged.
